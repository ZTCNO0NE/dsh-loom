# v1.2.31 release evidence

This patch fixes contradictory user-facing status after a Gate-owned Config rollback. It does not change Gate authority, installation, or rollback semantics.

## Failure

On Windows v1.2.30, the authoritative state was `restartRequired:false`, the current task outcome was `已回滚`, and harness applied targets were empty. However, the persisted job summary and one limitation still said the installed Config awaited a cold restart. Actor presentation combined those historical strings with live state and incorrectly concluded that another restart was required.

## Fix

- `meta_status` projects a terminal user-evolution job summary from its immutable plan instead of trusting a stale process-era summary.
- `rolledBack` takes precedence over obsolete `restartRequired` data during terminal job recovery.
- A rolled-back task card says the Gate restored its before snapshot and that no pending restart remains.
- Cold-restart limitations are filtered after rollback, including for existing immutable records.
- Future rollback operations update their persisted job summary immediately.

## Windows cold verification

The local package was installed into the Windows `web` and `loom` profiles and Web was cold-started from the generated active-evolution patch. A fresh headless Actor called the real tools against the existing immutable rollback record.

- `activeEvolution.restartRequired`: `false`
- `latestJob.id`: `job-1787230144504-64tjei`
- `latestJob.status`: `finished`
- `latestJob.summary`: `用户委托 config/agent-default-model：已回滚`
- Task progress: `已通过 Gate 恢复安装前快照。`
- Task next action: `当前任务不再有待重启生效的变更。`
- Task outcome: `已回滚`
- The obsolete cold-restart limitation was absent.
- Actor conclusion: no restart is required.
