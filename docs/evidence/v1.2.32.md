# v1.2.32 release evidence

## Scope

This release makes mini-SWE execution portable and gives complex implementation passes an elastic convergence budget without weakening the submission or adjudication boundary.

- Every local action uses an explicitly resolved Bash process rather than host `shell=True`.
- Windows auto-discovers Git Bash; POSIX resolves Bash from `PATH`. Advanced deployments can use `LOOM_BASH` (or compatible `LOOM_GIT_BASH`).
- Action-local `python3` maps to a resolved interpreter. `LOOM_PYTHON` is the explicit override; invalid explicit overrides fail closed.
- The model sees a compact runtime profile for platform, shell, workspace cwd/path style, Python, Node and Git, so it can reserve probing for a real error or unavailable capability.
- The default mini-SWE ceiling is 40 model calls. A 75% checkpoint and two-call/final-call notices encourage convergence, but Loom still requires the runtime's real `Submitted` terminal event.
- Non-submitted trajectories report terminal status plus consumed model/tool budget.

## Claim boundary

This evidence supports portable runtime execution and bounded Skill-task submission stability on the tested Windows/Linux environments. It does not establish that arbitrary models or complex multi-file Loop refactors converge within 40 calls, and it does not turn an unsubmitted workspace into a proposal. Verifier and Gate remain independent final authorities.
