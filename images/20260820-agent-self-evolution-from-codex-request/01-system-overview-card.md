# 卡 01：Agent 有两条回路

## 卡片任务

给已经用过 Agent、但把“能调用工具”和“能安全改进自己”混为一谈的读者，建立一张以后所有案例都会复用的地图。

**这张卡只解释一件事：**任务回路负责把当前工作做完；进化回路负责决定能否改变下一次工作的能力。两者必须分开，进化回路不能直接改运行中的 Agent。

## 阅读编排

读者应按如下顺序理解，而非同时读一堆名词：

1. **先看中央**：Agent runtime 只处理当前任务，它不是自我修改的裁判。
2. **再看内环**：请求被组装、模型做出动作、工具在外部执行、结果回到下一轮。这个环解释“普通 Agent 已经能做什么”。
3. **再看分叉**：失败、用户纠正或回归异常不会直接触发改代码；它们先以证据形式离开内环。
4. **再看外环**：证据经由假设、受限候选、独立验证与 Gate，才有机会影响下一次运行。
5. **最后看底座**：Verifier、Gate、回归集和权限边界是信任根，候选可以被它们检查，却不能反向改写它们。

阅读完成后，读者应自然得到一个判断：**“会反思”只发生在内环；“可靠地进化”需要外环与不可越过的底座。**

## 信息与因果

| 层 | 元素 | 它如何与下一层相连 | 绝不允许出现的捷径 |
|---|---|---|---|
| 内环 | 请求工作包、模型推理、工具执行、结果回灌 | 顺时针完成一次真实任务 | 候选直接覆盖 runtime |
| 分叉 | 失败事实、用户纠正、回归异常 | 只作为 evidence 进入外环 | 一次成功直接写进长期能力 |
| 外环 | 假设、受限候选、Verifier、Gate | 先验证，再在回合边界安排安装或回滚 | 候选修改 Verifier/Gate/回归集 |
| 底座 | TCB 信任根 | 对外环提供拒绝、安装、回滚的能力 | 被评估对象拥有底座写权限 |

## 精确构图

画布 1536×1024；中心视觉留给一个稳定的、无人格化的执行核心。

- **中央区（x=560–970, y=330–690）**：运行核心是半透明深蓝圆角椭圆舱。它只接收内环，不直接接触外环的 Gate。
- **内环（半径约 290×230）**：四个等距节点按左上→右上→右下→左下顺时针排列。环线是细蓝色数据纤维；每段仅一根箭头，避免多头箭头。`结果回灌`到`请求工作包`必须明显闭合。
- **证据出口（x=330, y=650）**：从内环左下的“结果回灌”分出一条琥珀色细流，到左侧外环；它标识“失败事实”，不是所有运行结果都自动触发进化。
- **外环（半径约 570×390）**：从左下开始逆时针走“假设→受限候选→独立验证→Gate”。外环线用琥珀到青色渐变，但每个节点单独有留白标签区；Gate 到中央只存在一条细绿色“approved install”线路，并在中央边缘停住，表示回合边界冷替换。
- **TCB 底座（x=120–1416, y=878–956）**：一条不可断开的深灰石墨带，内嵌锁芯、校准尺、档案槽的无文字图标。外环的 Verifier 与 Gate 从该带向上长出；候选节点位于带外。没有任何回箭头从候选回到底座。
- **视觉层级**：中央内环最亮；外环第二亮；TCB 深且稳；被拒绝候选使用暗红碎片下沉到归档槽，不做爆炸效果。

## 生成验收

1. 即使没有文字，也能辨认出“中心—内环—外环—底座”四层。
2. 内环闭合，外环从失败分叉，而非与内环混成一条大环。
3. 外环中只有一条绿色、受闸门控制的线路回到核心。
4. 底座连续，任何候选都没有跨越或改写它的视觉暗示。
5. 每个预期标签点周围至少保留 180×54 像素的干净背景区。
