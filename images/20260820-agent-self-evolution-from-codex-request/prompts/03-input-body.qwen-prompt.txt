生成一张无文字技术关系图背景，1536×1024 横版，解释“input body 是字段分工，不是一段长 prompt”。画面必须先显示一个由客户端装配的展开式请求容器，再显示历史状态以受控支路进入其中，最后到达协议翻译门；不要画成 API 文档截图或聊天界面。

采用白蓝灰的精密信封剖面隐喻，暖灰纸面、半透明玻璃隔舱、干净的工程论文插图质感。中央是一只横向展开的半透明请求容器，内部五个平行、等宽、彼此分隔的插槽，自左向右保留标签位置，分别暗示当轮消息/结果、稳定约束、能力目录、推理设置、执行设置：用信纸、封条、工具插槽、棱镜、调节旋钮等无文字图标表示。插槽之间不能融成一块，也不能画成五个普通矩形卡片。左侧有一条细而克制的历史支路，从一个由多层玻璃片组成的会话卷轴出发，经由小型展开器后，仅进入第一个插槽；这条支路与其他插槽不相连，表达接续不等于自动总结。请求容器右侧连接一扇窄而清楚的翻译门，门后只出现抽象的上游数据流，下一张才解释服务端翻译。

所有文字后期叠加；画面绝对不出现文字、字母、数字、schema、JSON、代码或 logo。容器顶部、五个隔舱、历史支路和翻译门附近必须预留平坦标签区。蓝色表示 input，琥珀表示稳定约束，青色表示能力目录，淡紫表示推理设置，绿色表示执行设置；历史支路为低亮度灰蓝。
