# 图 01：请求工作包不是一段聊天记录

## 这张图只回答一个问题

当读者把一句“修这个 bug”交给 Agent 时，模型实际拿到的不是这一句话。它接收的是一个**本轮工作包**：当前任务、长期约束、可调用工具、历史状态与刚刚发生的工具结果，被分别保存、组装并送入本轮推理。模型发起工具调用后，外部执行的结果再回到下一轮工作包。

本图刻意不画 adapter 的协议翻译细节。那是下一张图的主题；把两件事塞在一起会把“模型究竟看到了什么”和“服务端怎样转发它”混为一谈。

## 读者应该在三秒内读到的因果关系

1. 用户消息只是一条输入流，不能代表模型拥有的全部上下文。
2. 规则、工具和状态各有不同来源与更新节奏，不能用一段“记忆”概括。
3. 工具结果不是答案，它会变成下一轮的可见事实；因此 Agent 的行为依赖反馈回路。

## 画面结构

画幅为 1536×1024，采用“透明实验工作台 + 数据纤维”的论文机制图隐喻，避免把信息画成一排无意义卡片。

- **左侧，输入层（x=70–540）**：2×2 的四个独立载体，位置刻意错开，不形成流程先后。
  - 蓝色便签与定位针：当前任务，代表本轮意图。
  - 琥珀色档案夹与盾牌：稳定约束，代表 instructions、skill 和权限边界。
  - 青色工具盒与扳手：工具与边界，代表名称、参数模式和执行许可。
  - 绿色半透明时间胶片与回环箭头：历史与结果，代表历史消息、状态和工具回传。
- **中部，装配层（x=585–970）**：悬浮的半透明“上下文胶囊”，内部有五层薄片，四束不同颜色的发光纤维从左侧进入，先保持分离，穿过一层窄的校准膜后才在胶囊内重叠。这个“先分开、后组装”是图的核心。
- **右侧，模型与执行边界（x=1070–1460）**：模型只画成一个克制的深蓝棱镜，不画大脑、不拟人化。胶囊进入棱镜后，输出两条不同性质的路径：细蓝光束表示文本回复；粗青光束穿过一扇闸门，表示受参数约束的工具调用。
- **下方，外部世界与反馈（y=770–920）**：工具调用落入一个浅石墨色的执行盘；盘内是无文字的终端、文件和传感器图标。执行盘产出的绿色回流粒子沿底部回到左侧绿色时间胶片，明确“结果更新状态，再进入下一轮”，而不是一次调用后模型永久学会。

## 精确文字覆盖层

文字由 PIL/SVG 叠加，绝不交给 Qwen 生成。建议仅保留以下 7 个短标签：

- 标题：`一轮请求，模型看到了什么？`
- 当前任务
- 稳定约束
- 工具与边界
- 历史与结果
- 本轮工作包
- 执行反馈

图注（放在文章 Markdown 中，不放画内）：`机制示意：不同客户端与部署的字段细节会变化；图中表达的是“输入分别存在、按轮组装、结果回流”的通用结构。`

## 生成后验收

- 四种输入载体可被一眼区分，且不会被误读为固定步骤。
- 四束纤维在进入中央胶囊前明确分离，胶囊内才叠加。
- 工具调用与文本回复是两条不同出口；工具调用经过闸门。
- 绿色反馈回到“历史与结果”位置，不回到模型棱镜。
- 画面任何位置均无 AI 生成文字，预留标签区没有被背景元素侵占。
